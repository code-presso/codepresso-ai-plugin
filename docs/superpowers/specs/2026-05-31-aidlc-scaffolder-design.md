> **상태:** 설계 합의 완료 — 구현 전 검토 대기
> **작성일:** 2026-05-31
> **관련 문서:** [`2026-05-31-aidlc-ai-native-plugin-design.md`](./2026-05-31-aidlc-ai-native-plugin-design.md) — 이 문서가 쓰는 "16항목 템플릿"과 점수표가 나온 리서치 문서.

## 한눈에 요약

이 플러그인에 새 기능을 추가합니다: **어떤 프로젝트 폴더를 받아서, "AI 에이전트가 일하기 좋은 저장소"가 갖춰야 할 기본 문서·설정 파일들을 자동으로 깔아주는 도구**입니다.

흐름은 다섯 단계입니다: **① 진단(뭐가 있고 뭐가 없는지 점수 매김) → ② 질문(자동으로 알 수 없는 것만 사용자에게 물어봄) → ③ 미리보기(뭘 만들지 보여주고 확인받음) → ④ 생성(없는 것만 만듦) → ⑤ 재진단(만든 뒤 점수 다시 보여줌)**.

핵심 약속: **이미 있는 파일은 절대 건드리지 않습니다.** 없는 것만 새로 만듭니다. 그래서 여러 번 돌려도 안전합니다.

여기서 "AI 에이전트가 일하기 좋은 저장소"의 기준 16가지는 이미 코드프레소 모노레포에서 뽑아낸 체크리스트입니다(관련 문서 참고). 예: `AGENTS.md`(에이전트용 안내서), `CLAUDE.md`, 의사결정 기록(ADR), 문서 정책, 코드 구조 요약, CI 검사 등.

---

## 1. 왜 만드나 (목적)

지금 이 플러그인은 "코드프레소 팀 전용 도구"(Notion 연동, 스프린트, PR 추적)입니다. 이 기능을 추가하면 플러그인의 성격이 바뀝니다:

**"코드프레소 전용 도구" → "어느 프로젝트에나 AI 친화적 기본 구조를 깔아주는 범용 도구"**

부수 효과로 외부 의존성도 줄어듭니다. 이 도구의 핵심 동작에는 Notion·Figma 같은 외부 서비스가 전혀 필요 없습니다. 그런 연동은 "원하면 켜는 선택 사항"이 됩니다.

## 2. 합의된 결정 사항

| # | 항목 | 결정 |
|---|------|------|
| D1 | 이미 있는 파일 처리 | **건드리지 않음.** 없는 것만 새로 만들고, 있는 것은 그대로 두고 결과 보고에만 표시. |
| D2 | 만드는 파일의 내용 수준 | **두 종류로 나눔.** ㉠ 정해진 양식 파일(의사결정 양식, 문서 정책, 권한 설정 등)은 **미리 준비된 견본을 복사.** ㉡ 그 프로젝트에 맞춰야 하는 파일(`AGENTS.md`, `CLAUDE.md`, 코드 구조 요약)은 **AI가 코드를 살펴보고 직접 작성.** |
| D3 | 1차 범위 | **기본 구조 깔아주기까지만.** 단계별 개발 흐름을 돕는 추가 기능(설계서 작성 도우미 등)은 다음 버전. |
| D4 | 만드는 범위 | **없는 16항목 전부.** |
| D5 | 대상 저장소 종류 | **모든 형태.** 여러 하위 프로젝트로 이뤄진 저장소인지, 단일 프로젝트인지 자동으로 구분해서 맞춤 처리. |
| D6 | 만드는 방식 | **안내 문서(스킬) + 작은 보조 프로그램(CLI).** 판단이 필요한 일은 AI가, 기계적으로 정해지는 일은 보조 프로그램이 담당(이 플러그인이 이미 쓰는 방식). |

### 2.1 기존 기능·연동과의 관계 (무영향)

- **이 플러그인의 기존 기능은 그대로입니다.** 이 작업은 순수 추가입니다 — 새 스킬(`aidlc-init`/`aidlc-doctor`)·새 보조 프로그램·새 견본·새 테스트만 더합니다. 기존 스킬·훅·스크립트(notion-sync·oncall·daily-chat·scan-inbox·llm-wiki·generate-epic·figma)는 건드리지 않습니다. 손대는 기존 파일은 설명용 `CLAUDE.md` 하나뿐이고, 상태 파일 이름(`aidlc-scorecard.json`)도 겹치지 않습니다.
- **대상 저장소(예: 모노레포)의 기존 외부 연동도 그대로입니다.** `aidlc-init`은 "없는 파일만 새로" 만들 뿐, 대상의 기존 연동 설정(`.codepresso.json`, Notion/Google/AWS 설정)을 읽거나 끄거나 고치지 않습니다. 이미 Notion이 켜진 모노레포에 돌려도 비파괴 원칙상 그 설정은 손대지 않으므로, 모노레포의 Notion 동기화·온콜·데일리챗은 계속 작동합니다.
- **"외부 연동 기본 꺼짐"의 의미.** 이 기본값(§7-3)은 *새 저장소에 처음 깔 때 무엇을 시드하느냐*에만 적용됩니다. 이미 연동이 있는 저장소를 끄는 동작이 아닙니다.
- **나중(다음 버전)의 디커플링**(관련 문서 §3, 연동을 갈아끼우기 쉽게 만드는 작업)은 기존 기능을 건드리지만, 그것도 동작을 보존하는 비파괴 리팩터링이며 **이번 1차 범위 밖**입니다.

## 3. 성공 기준

- 아무 저장소에서나 `/codepresso:aidlc-init <폴더경로>`를 실행하면, 16항목 점수표가 나오고 없는 항목이 안전하게 생성된다.
- 같은 저장소에서 다시 실행해도 점수가 똑같고(기계적 판정), 이미 있는 파일은 손대지 않는다.
- 여러 하위 프로젝트로 된 저장소면, 하위 프로젝트마다 `CLAUDE.md`까지 맞춰 만든다.
- 핵심 동작이 Notion·Figma 같은 외부 연동 없이도 돌아간다.
- 보조 프로그램의 핵심 로직(진단·판정·복사)은 자동 테스트로 검증된다.
- 코드에 비밀번호·토큰이 평문으로 박혀 있으면(`ntn_…`, GitHub 토큰 등) 🔴 경고로 띄우고, 그 값을 새 파일 어디에도 옮겨 적지 않는다.

## 4. 구성 요소와 동작 흐름

### 4.1 새로 만들/고칠 파일

| 파일 | 하는 일 | 신규/수정 |
|------|---------|-----------|
| `skills/aidlc-init/SKILL.md` | 전체 흐름을 AI가 따라가도록 적은 안내서. 질문과 "AI 직접 작성" 부분을 담당. | 신규 |
| `skills/aidlc-doctor/SKILL.md` | 만들지는 않고 **진단만** 하는 모드. 점수와 빠진 항목만 보고. | 신규 |
| `scripts/aidlc-cli.mjs` | 기계적인 일을 처리하는 보조 프로그램. 하위 명령: `detect`(파악)/`scan`(진단)/`plan`(미리보기)/`apply-static`(견본 복사)/`score`(점수 계산). | 신규 |
| `scripts/lib/aidlc-detect.mjs` | 저장소 종류·사용 기술·호스팅 위치를 파악하는 순수 로직. | 신규 |
| `scripts/lib/aidlc-scan.mjs` | 16항목이 있는지/일부인지/없는지 판정하고, 평문 비밀값도 점검. | 신규 |
| `scripts/lib/aidlc-template.mjs` | 견본의 빈칸 채우기 + **있는 파일은 건드리지 않도록 막는 안전장치.** | 신규 |
| `templates/aidlc/**` | 미리 준비된 견본 파일들(아래 §9). | 신규 |
| `tests/lib/aidlc-*.test.mjs`, `tests/aidlc-cli.test.mjs` | 위 로직들의 자동 테스트. | 신규 |
| `CLAUDE.md` | 새 기능·파일·상태 파일을 설명에 추가. | 수정 |

> 용어: **스킬** = AI가 단계를 따라가도록 적어둔 안내 문서. **CLI(보조 프로그램)** = 사람이나 AI가 호출하면 정해진 일을 정확히 처리하는 작은 Node 프로그램. 둘로 나누는 이유는, 점수 계산·파일 복사처럼 "답이 정해진 일"은 프로그램이 해야 매번 똑같고 테스트가 되기 때문입니다. 판단이 필요한 일(글쓰기·질문)만 AI가 합니다.

### 4.2 다섯 단계 동작 흐름

```
/codepresso:aidlc-init <폴더경로>
 ① 파악(detect)   : 저장소 종류·기술 스택·호스팅·티켓 사용 여부 알아내기
 ② 진단(scan)     : 16항목 점수표 만들기(+ 비밀값 점검) → 사용자에게 현재 % 보여주기
 ③ 질문(interview): 자동으로 알 수 없는 것만 물어보기 (아래 §7)
 ④ 미리보기(plan) : 새로 만들 파일 목록을 트리로 보여주고 → 사용자 확인받기
 ⑤ 생성(apply)
     ㉠ 견본 복사 : 정해진 양식 파일을 복사하고 빈칸 채움 (있으면 건너뜀)
     ㉡ AI 작성   : AGENTS.md·CLAUDE.md·(여러 프로젝트면)하위별 CLAUDE.md·코드구조 요약
 ⑥ 재진단(score) : 만든 뒤 점수 다시 계산 → 새 % + 아직 빠진 항목
```

> 결과 기록 파일: `<폴더>/.codepresso/state/aidlc-scorecard.json`. 마지막 진단 결과를 저장해, 다시 실행할 때 변화를 비교합니다.

### 4.3 전 과정에 적용되는 원칙

- **있는 파일은 안 건드림(D1):** 모든 파일 생성은 `aidlc-template.mjs`의 안전장치를 거칩니다. 같은 이름 파일이 이미 있으면 만들지 않고 "건너뜀"으로 보고만 합니다.
- **진단은 기계적으로:** 보조 프로그램은 인터넷을 쓰지 않고 로컬 파일과 git만 봅니다. 그래서 같은 저장소면 결과가 항상 같고 테스트가 됩니다. AI는 글쓰기와 질문에만 씁니다.
- **모르면 추측하지 않음:** 딱 잘라 판정하기 어려운 항목은 "추측"하지 말고 "**일부 갖춤(확인 필요)**"으로 표시한 뒤, 질문 단계에서 사용자에게 확인합니다. (앞선 리서치에서 AI가 저장소를 헷갈리고 점수를 부풀린 적이 있어, 그 교훈을 반영한 것입니다.)

## 5. 저장소 파악 (`aidlc-detect.mjs`)

| 알아내는 것 | 방법 |
|------|------|
| 저장소 종류 | `.gitmodules`에 하위 프로젝트가 여럿이거나, 폴더별로 별도 프로젝트 설정 파일이 있으면 **"여러 하위 프로젝트형"**, 아니면 **"단일형"** |
| 하위 프로젝트 목록 | `.gitmodules` 경로 또는 감지된 하위 패키지 |
| 사용 기술 | 설정 파일로 추정: `package.json`=Node, `pom.xml`/`gradle`=Java, `go.mod`=Go, `pyproject`/`requirements`=Python, `*.tf`=Terraform, `Cargo.toml`=Rust (여러 하위 프로젝트면 각각) |
| 호스팅 위치 | git 원격 주소로 GitHub/GitLab/Bitbucket 판별 |
| 티켓 사용 여부 | 최근 커밋·PR 제목에 `ABC-123` 같은 패턴이 있는지 추정 → **확실치 않으니 질문에서 확인** |

판단이 애매하면 사용자에게 물어봅니다. 대상이 git 저장소가 아니면 경고하고 계속할지 확인합니다.

## 6. 진단과 점수표 (`aidlc-scan.mjs`)

16항목(관련 문서 §2.1) 각각에 대해 "갖춤 / 일부 갖춤 / 없음"을 판정하고, 근거가 된 파일 경로를 함께 적습니다. 점수는 갖춤 1점, 일부 0.5점, 없음 0점, 해당 없음은 제외하고 백분율로 환산합니다.

판정 예시:
- **하위별 CLAUDE.md:** 여러 하위 프로젝트형에서 전부 있으면 "갖춤", 일부만 있으면 "일부", 단일형이면 "해당 없음".
- **의사결정 기록(ADR):** `docs/decisions/` 폴더 + 양식 파일 + 기록 1개 이상이면 "갖춤", 폴더만 있으면 "일부".
- **권한 설정:** 공유용 설정 파일이 커밋돼 있으면 "갖춤", 개인용 설정만 있으면 "일부".
- **PR 검사(CI):** PR을 올릴 때 테스트가 돌도록 설정돼 있으면 "갖춤".
- **딱 잘라 판정 어려운 항목**(추적성, 기능 켜고 끄기): 보수적으로 "일부 갖춤(확인 필요)"으로 두고 질문에서 확정.

**비밀값 점검:** 진단 중에 코드나 설정에 토큰·비밀번호가 평문으로 박혀 있으면(`ntn_…`, GitHub 토큰 등) 점수표에 🔴 경고로 적습니다(값은 가려서). 그 값은 새로 만드는 어떤 파일에도 옮겨 적지 않습니다.

결과는 사람이 읽는 표 + 기계가 읽는 `aidlc-scorecard.json` 두 형태로 냅니다.

## 7. 질문 단계 (자동으로 알 수 없는 것만, 짧게)

1. **파악 결과 확인** — 알아낸 저장소 종류·기술·하위 프로젝트가 맞는지, 틀렸으면 바로잡기.
2. **어떤 AI 도구를 쓰나** — `AGENTS.md`와 `CLAUDE.md`는 항상 만들고, 추가로 Cursor·Amazon Q·Copilot·Cline용 안내 파일이 필요하면 선택(여러 개 선택 가능). 기본은 `AGENTS.md`+`CLAUDE.md`만.
3. **외부 연동을 켤까** — Notion·Figma·Google·AWS 연동: **기본은 전부 꺼짐**(로컬 우선). 켜면 관련 설정 칸만 미리 넣어줌. 실제 연동 동작 기능은 다음 버전.
4. **티켓 규칙** — 티켓을 쓰는지, 쓴다면 접두사(예: `TSK-`)와 PR 제목 규칙. 안 쓰면 추적성 관련 내용은 생략.

## 8. 파일 생성 단계

### 8.1 견본 복사 (보조 프로그램이 처리 — 기계적)
없는 항목 중 "정해진 양식" 파일을 `templates/aidlc/`에서 복사하고 빈칸을 채웁니다(프로젝트 이름·기술·티켓 접두사·호스팅·테스트 명령 등). 같은 파일이 이미 있으면 건너뛰고 보고만 합니다.

### 8.2 AI 작성 (그 프로젝트에 맞춰야 하는 파일)
파악·진단 결과를 바탕으로 AI가 직접 씁니다. **원칙: 실제 내용은 `AGENTS.md` 한 곳에만 쓰고, 나머지는 전부 그걸 가리키게 합니다.** 그래야 Claude·Cursor·Codex·Aider 등 어떤 AI 도구를 쓰든 같은 한 곳을 보게 됩니다(내용이 여러 파일에 흩어져 어긋나는 걸 막음).
- `AGENTS.md` — **유일한 본문.** 빌드·테스트·실행 명령, 규칙, 구조 요약을 여기에 다 씁니다(쓰는 기술에 맞춰). 모든 AI 도구의 공통 진입점.
- 루트 `CLAUDE.md` — **얇은 포인터.** 자체 내용을 갖지 않고 "이 저장소의 안내는 `AGENTS.md`를 보라"고 가리킴.
- 선택한 다른 도구 안내 파일(`.cursor/rules`·`.amazonq/rules`·`.github/copilot-instructions.md`·`.clinerules`)도 마찬가지로 **`AGENTS.md`를 가리키는 얇은 포인터**(각 도구 형식에 맞춰).
- (여러 하위 프로젝트면) **하위별 `CLAUDE.md`** — 각 하위 프로젝트의 기술에 맞춘 내용. 이건 하위 폴더의 권위 있는 본문 역할(상위 `AGENTS.md`는 저장소 전체, 하위 `CLAUDE.md`는 그 하위 프로젝트 전용).
- `.codesight` — 코드 구조를 한눈에 보여주는 요약 문서.
  - 하위 프로젝트가 아주 많은 큰 저장소에서는 전부 담으면 너무 길어지므로, **핵심만 요약해서 쓰되 무엇을 뺐는지 반드시 적어 둡니다**(말없이 잘라내지 않습니다).

이 파일들도 마찬가지로, 이미 있으면 새로 쓰지 않습니다.

### 8.3 여러 하위 프로젝트형 저장소 처리
구조·정책 파일(의사결정 기록·문서 정책·권한·CI·푸시 전 점검)은 **맨 위 폴더에 한 번만** 만듭니다. 하위별 `CLAUDE.md`만 하위 프로젝트를 돌며 만듭니다.

### 8.4 미리보기 확인 (④단계)
파일을 만들기 전에, 보조 프로그램이 "새로 만들 파일 목록"을 트리로 보여줍니다(각 파일이 견본 복사인지 AI 작성인지 표시). **사용자가 확인해야만** 실제로 파일을 만들기 시작합니다. 확인 전에는 디스크에 아무것도 쓰지 않습니다.

순서: 견본 복사(빠르고 기계적) 먼저 → AI 작성 → 재진단.

## 9. 미리 준비할 견본 (`templates/aidlc/`)

- `decisions/TEMPLATE.md`(의사결정 기록 양식) + `decisions/README.md`(목록)
- `documentation-policy.md`(문서 종류별 보관 규칙)
- `ai-agent-policy.md`(에이전트 작업 규칙 기본형 + 프로젝트별로 채울 빈칸)
- `.claude/settings.json`(안전한 권한 설정 기본형 — **비밀값 없음**)
- `.github/workflows/ci.yml`(PR 올릴 때 테스트 도는 설정)
- `scripts/check-before-push.sh`(푸시 전 비밀값·미반영 변경 점검)
- `docs/superpowers/{specs,plans}/README.md`(폴더 규칙 안내)

> `.gitignore` 항목 추가는 v1에서 제외. 기존 `.gitignore`에 "추가"하는 것은 create-only 비파괴 모델(있으면 건너뜀)과 맞지 않아, 별도 append-안전 처리가 필요하므로 후속으로 미룸.

## 10. 진단 전용 모드(doctor)

`/codepresso:aidlc-doctor <폴더경로>`는 **만들지 않고 진단만** 합니다(파악→진단→점수). 현재 점수와 빠진 항목만 보고하고 `aidlc-scorecard.json`을 갱신합니다. 진단이 기계적이고 생성이 안전하므로, 시간이 지나며 저장소가 기준에서 벗어났는지 가볍게 다시 확인하는 용도입니다.

## 11. 문제 상황 처리

- git 저장소가 아니면 경고하고 계속할지 확인(일부 항목은 제한).
- 기술 추정이 애매하면 질문으로 보완.
- 견본 복사: 파일이 이미 있으면 건너뜀(오류 아님), 견본이 없으면 기록하고 계속.
- 큰 하위 프로젝트의 코드 구조 요약은 분량을 줄이되 **뺀 부분을 기록**(말없이 자르지 않음).
- 중간에 망가지지 않게: 미리보기에서 동의받은 뒤 → 파일을 하나씩 안전하게 씀 → 실패하면 기록하고 나머지는 계속 → 마지막에 성공·실패 목록 보고.
- 비밀값을 발견하면 🔴로 띄우고 어디에도 옮겨 적지 않음.

## 12. 테스트

- `aidlc-detect` — 견본 저장소들로: 단일 Node / 여러 하위 프로젝트 / Terraform / 혼합.
- `aidlc-scan` — 빈 저장소(전부 없음) / 완전 저장소(전부 갖춤) / 일부 / 비밀값 포함.
- `aidlc-template` — 빈칸 채우기, **이미 있는 파일 건너뛰기**.
- `aidlc-cli` — 각 하위 명령을 임시 폴더에서 실제로 돌려보는 점검.
- AI가 쓰는 부분은 자동 테스트 대상이 아님(판단 영역). 대신 "진단 결과 → AI 작성"으로 넘기는 입력 형식만 검증.

## 13. 1차 범위 밖 (다음 버전)

- **스프린트 진척·이슈 트래킹 같은 살아있는 PM 기능.** 이건 파일로 깔아주는 "구조"가 아니라 운영 중 갱신되는 상태라, 스캐폴더 대상이 아닙니다. 저장소 쪽 연결 조각(#12 추적성: PR 제목 티켓ID → 머지 → 상태 연동)만 템플릿에 포함하고, 실제 트래킹은 기존 플러그인 기능(`sprint-dashboard`·`notion-sync`·`generate-epic`)과 다음 버전의 단계별 워크플로우 스킬이 담당합니다. (Notion 의존을 줄이는 "로컬 우선 진척 추적"은 v2에서 별도 검토.)
- 단계별 개발 흐름 도우미(설계서·계획서·요구사항 작성 도우미 등).
- 외부 연동 실제 동작 기능(Notion·Figma 등). 1차는 설정 칸과 켜고 끄기만.
- 이미 "일부 갖춤"인 파일을 보강·합치기. 1차는 없는 것만 새로 만듦.
- git 저장소가 아닌 폴더 완전 지원.
